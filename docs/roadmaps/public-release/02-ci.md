# 02. CI

## Goal

Every push and PR on GitHub runs the project's checks — cargo tests, clippy,
and the viewer's vitest suite — so the later, riskier stages land onto a
guarded main.

## Decisions in force

- **A plain CI workflow separate from the release workflow** was chosen in
  the grilling session; the repo currently has no workflows at all.
- Scope agreed: cargo tests, clippy, viewer suite. rustfmt and `nix flake
  check` are open extras — decide at stage start whether the nix path (slow,
  hermetic, covers the VM test) rides alongside a fast rustup+pnpm path or is
  left to local use.
- The toolchain versions of record live in the flake (nixos-25.11's rust,
  nodejs, pnpm); CI should not drift far from them.

## Proposed tasks (provisional)

1. **Rust job** — checkout, toolchain, cache, `cargo test --workspace`,
   `cargo clippy`. Accepts: red on a failing test; green on main as it
   stands.
2. **Viewer job** — pnpm install and the vitest suite under `web/`. Accepts:
   red on a failing component test.

## Re-verify at start

- Whether stage 01 landed (job names and any binary-name references).
- Current runner images and action versions — pin what the workflow uses.
- Whether the pnpm lockfile version needs a pinned pnpm in CI (match the
  flake's).
